# 題庫品質規格

題庫（`data/*.json`）的每一題都必須符合這份規格。App 直接從 GitHub `main` 讀取題庫，
**合併進 main 就是上線**，所以任何修改都要先通過下方的檢查流程。

## 玩家看到的是什麼

- 題目卡**只顯示假名**（`kana`），不顯示漢字。
- 四個選項 = 正解 + 3 個錯誤選項，隨機排列。
- 中文介面用 `meaning_zh` + `distractors`；英文介面用 `meaning_en` + `distractors_en`。兩套互相獨立。

## 一題合格的條件

1. **正解正確**：`meaning_zh`、`meaning_en` 各自是這個單字的正確意思。
2. **只看假名時，四個選項恰好一個是對的**：
   - 錯誤選項不能是正解的同義詞或近義詞。
   - 錯誤選項不能是同讀音其他單字的意思（例：かう＝飼う／買う，かてい＝仮定／家庭／過程）。
   - 錯誤選項不能是這個單字的其他正確意思（例：以上 也有「上述」的意思）。
   - 錯誤選項不能是正解的上位概念（例：生物 的選項不能是「動物」）。
3. **錯誤選項看起來合理**：同詞性、同領域，但意思明確不同。首選反義詞或同一類別的其他概念。
4. **格式**：
   - 中文只用正體中文，不能有假名或日文專用漢字（予、対、点⋯）。
   - 英文不能有漢字或假名。
   - 三個錯誤選項彼此不重複，也不等於正解或正解的任何一部分。

## 檢查流程

| 關卡 | 做法 | 何時 |
| --- | --- | --- |
| L1 自動檢查 | `npm run validate:words`；本機 pre-commit hook + GitHub Actions。含「漢字欄位的讀音要能對上假名」，擋下把中文寫進日文欄位 | 每次修改 |
| L2 同音詞檢查 | 用 JMdict 列出同讀音的單字，和錯誤選項比對 | 每次修改 |
| L2b 難度檢查 | `python3 scripts/check_jlpt_level.py <ref_dir>`，和 Waller（tanos）JLPT 單字表比對分級；列出比參考更難、更簡單、或表上沒有的字，逐條人工判斷（參考表有已知錯漏，不能直接照改） | 新增單字或調整難度時 |
| L3 雙評審盲測 | 兩個獨立評審（不同模型）只看假名和四個選項作答，並標記模稜兩可的題目；中英各一次 | 每次修改（只測改到的題目即可） |
| L4 修正迴圈 | 沒通過的題目修正後重測；評審意見不一致、或修 3 次仍不過的才交給人裁決 | L3 之後 |
| L5 線上監控 | 每題答對率與玩家回報 | 上線後（規劃中） |

通過 L1–L4 才能開 PR 合併進 main。
